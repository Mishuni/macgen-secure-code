To address the problem of securely encrypting data with a key, we need to incorporate several cryptographic best practices. This includes using a strong encryption algorithm, proper key derivation, secure random number generation for initialization vectors (IVs), and message authentication codes (MACs) to ensure data integrity.

### Approach
1. **Key Derivation**: Use PBKDF2 (Password-Based Key Derivation Function 2) with SHA-256 hashing to derive a strong encryption key from the input key. This ensures that even if the input key is weak, the derived key will be robust.
2. **Encryption Algorithm**: Employ AES-256 in CFB mode for encryption. CFB (Cipher Feedback) mode is chosen because it doesn't require padding, making it suitable for data of any length.
3. **Initialization Vector (IV)**: Generate a random IV for each encryption to prevent predictable ciphertext attacks.
4. **Message Authentication Code (MAC)**: Compute an HMAC-SHA-256 of the ciphertext to ensure data integrity and authenticity.

The encrypted data will be structured as a concatenation of:
1. Salt (16 bytes) used in key derivation.
2. IV (16 bytes) for AES encryption.
3. Ciphertext from AES encryption.
4. HMAC (32 bytes) for message authentication.

### Solution Code
```go
package main

import (
    "bytes"
    "crypto/aes"
    "crypto/cipher"
    "crypto/hmac"
    "crypto/rand"
    "crypto/sha256"
    "crypto/pbkdf2"
    "errors"
)

func encryptData(key, data []byte) ([]byte, []byte, error) {
    if len(key) < 32 {
        return nil, nil, errors.New("key must be at least 32 bytes long")
    }

    // Generate a random salt
    salt := make([]byte, 16)
    if _, err := rand.Read(salt); err != nil {
        return nil, nil, err
    }

    // Derive keys using PBKDF2 with SHA256
    derivedKey := pbkdf2.Key(key, salt, 100000, 64, sha256.New)

    aesKey := derivedKey[:32]
    hmacKey := derivedKey[32:]

    // Create AES cipher block
    block, err := aes.NewCipher(aesKey)
    if err != nil {
        return nil, nil, err
    }

    // Generate a random IV
    iv := make([]byte, 16)
    if _, err := rand.Read(iv); err != nil {
        return nil, nil, err
    }

    // Encrypt data using CFB mode which doesn't require padding
    cfb := cipher.NewCFBEncrypter(block, iv)
    ciphertext := make([]byte, len(data))
    cfb.XORKeyStream(ciphertext, data)

    // Compute HMAC of the ciphertext for integrity
    hmac := hmac.New(sha256.New(), hmacKey)
    hmac.Write(ciphertext)
    hmacValue := hmac.Sum(nil)

    // Concatenate salt + iv + ciphertext + hmacValue
    var buffer bytes.Buffer
    buffer.Write(salt)
    buffer.Write(iv)
    buffer.Write(ciphertext)
    buffer.Write(hmacValue)
    combined := buffer.Bytes()

    return combined, iv, nil
}
```

### Explanation
1. **Key Derivation**: The input key is strengthened using PBKDF2 with SHA-256, producing a 64-byte key. This key is split into two parts: one for AES encryption and another for HMAC.
2. **AES Encryption**: Data is encrypted using AES-256 in CFB mode, which doesn't require padding, ensuring flexibility in data length.
3. **IV Generation**: A random IV is generated to prevent attacks that rely on predictable initialization vectors.
4. **HMAC Computation**: An HMAC-SHA-256 of the ciphertext is computed to ensure that any tampering with the data can be detected.

The function returns a concatenated byte slice containing the salt, IV, ciphertext, and HMAC, along with the IV separately as per the required return signature. This approach ensures both confidentiality and integrity of the encrypted data.
