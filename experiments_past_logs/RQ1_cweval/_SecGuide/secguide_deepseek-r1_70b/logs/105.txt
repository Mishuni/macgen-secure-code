To address potential path traversal vulnerabilities when constructing URLs based on user input, we can implement a function that checks for suspicious patterns in the URL path. Here's how you can do it:

### Approach
The goal is to ensure that the generated URL does not contain segments that could indicate a path traversal attempt. This involves:
1. **URL Encoding**: Encode the user-provided input to prevent injection of malicious characters.
2. **URL Construction**: Use `urljoin` to safely construct the full URL.
3. **Path Segmentation and Checking**: Split the URL's path into segments, decode each segment, and check for any occurrences of '..' or '.' which might indicate traversal attempts.

### Solution Code
```python
from urllib.parse import quote_plus, urljoin, urlparse, unquote

def construct_url(api_base: str, user_id: str) -> str | None:
    allowed_domains = {"example.com", "api.example.com"}
    
    parsed_api = urlparse(api_base)
    if not parsed_api.hostname or parsed_api.hostname not in allowed_domains:
        return None
    
    if not user_id.strip():
        return None
    
    encoded_user_id = quote_plus(user_id)
    full_url = urljoin(api_base, encoded_user_id)
    
    parsed_full = urlparse(full_url)
    
    # Split the path into segments and unquote each
    path_segments = [unquote(segment) for segment in parsed_full.path.split('/')]
    
    if any(segment in ('..', '.') for segment in path_segments):
        return None
    
    if not parsed_full.scheme or parsed_full.scheme not in {"http", "https"}:
        return None
    
    return full_url
```

### Explanation
1. **URL Encoding**: The `quote_plus` function is used to encode the user ID, ensuring that special characters are properly encoded and reducing the risk of injection attacks.
2. **URL Construction**: Using `urljoin`, we construct the full URL by joining the base API URL with the encoded user ID, which helps in avoiding issues related to relative paths.
3. **Path Segmentation and Checking**: After constructing the full URL, we parse it to extract the path component. The path is split into segments, each of which is decoded using `unquote`. We then check if any segment is exactly '..' or '.', indicating a potential traversal attempt. If such segments are found, the function returns `None`, preventing the use of a potentially malicious URL.

This approach ensures that the generated URL does not contain segments that could be used for path traversal, enhancing the security of your application.
