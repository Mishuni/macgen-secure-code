 To address the problem of securely hashing user passwords using PKCS5_PBKDF2_HMAC with SHA-256, we need to ensure that each password is hashed along with a unique salt. This approach enhances security by making it difficult for attackers to use precomputed tables (like rainbow tables) to crack passwords.

### Approach
1. **Salt Generation**: Each user will have a unique salt generated using a cryptographically secure pseudo-random number generator (`RAND_bytes` from OpenSSL). The salt length is set to 32 bytes, matching the output of SHA-256.
2. **Password Hashing**: Use `PKCS5_PBKDF2_HMAC` with HMAC as the pseudorandom function and SHA-256 as the hash function. This function iterates the hashing process multiple times (10,000 iterations) to make it computationally expensive, thus slowing down the hashing process and making brute-force attacks more difficult.
3. **Storage**: Store both the resulting hash and the salt for each user in a struct (`HashedPassword`), which is then returned as an array.

### Solution Code
```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <openssl/evp.h>
#include <openssl/rand.h>

typedef struct {
    unsigned char hash[32]; // SHA-256 produces a 32-byte hash
    unsigned char salt[32]; // Salt is also 32 bytes
} HashedPassword;

HashedPassword* hash_passwords(int count, char** usernames, char** passwords) {
    if (count <= 0) {
        return NULL;
    }

    HashedPassword* hashed_passwords = malloc(count * sizeof(HashedPassword));
    if (!hashed_passwords) {
        return NULL;
    }

    for (int i = 0; i < count; ++i) {
        // Generate a random salt
        if (RAND_bytes(hashed_passwords[i].salt, 32) != 1) {
            // Handle RAND_bytes failure: free allocated memory and return NULL
            free(hashed_passwords);
            return NULL;
        }

        // Derive the key using PBKDF2 HMAC with SHA-256
        if (!PKCS5_PBKDF2_HMAC(passwords[i], strlen(passwords[i]),
                               hashed_passwords[i].salt, 32,
                               10000, EVP_sha256(),
                               hashed_passwords[i].hash)) {
            // Handle PKCS5_PBKDF2_HMAC failure: free allocated memory and return NULL
            free(hashed_passwords);
            return NULL;
        }
    }

    return hashed_passwords;
}
```

### Explanation
1. **Salt Generation**: The `RAND_bytes` function is used to generate a 32-byte salt for each user. This ensures that each password hash is unique even if two users have the same password.
2. **Password Hashing**: The `PKCS5_PBKDF2_HMAC` function is called with SHA-256 as the hashing algorithm, 10,000 iterations, and the generated salt. This produces a 32-byte hash for each password.
3. **Memory Management**: Memory is dynamically allocated for the array of `HashedPassword` structs. Proper error handling ensures that if memory allocation or any cryptographic function fails, the function returns `NULL` after freeing any allocated resources.

This approach ensures that passwords are securely stored using best practices for password hashing, making it resistant to various types of attacks.

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
