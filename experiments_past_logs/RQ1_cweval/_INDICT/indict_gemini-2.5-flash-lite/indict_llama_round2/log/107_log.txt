    Args:

    # A more robust and commonly accepted regex for email validation.
    # This regex aims to balance RFC compliance with practical usage and security.
    # It avoids overly complex constructs that could lead to catastrophic backtracking.
    #
    # Breakdown:
    # ^: Start of the string.
    # Local part:
    #   [a-zA-Z0-9._%+-]+: Allows alphanumeric characters, dot, underscore, percent, plus, and hyphen.
    #   This is a common and practical set of allowed characters for the local part.
    # @: The separator.
    # Domain part:
    #   [a-zA-Z0-9.-]+: Allows alphanumeric characters, dot, and hyphen for domain names.
    #   \.: Matches the dot separating domain labels.
    #   [a-zA-Z]{2,}: Matches the Top-Level Domain (TLD) which must be at least two alphabetic characters.
    # $: End of the string.
    #
    # This regex is a good compromise for most common email validation needs.
    # It does not explicitly handle quoted local parts or IP address literals as domains,
